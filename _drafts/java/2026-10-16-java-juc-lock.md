## 什么是锁

我觉得有必要先理解一下什么叫做锁（_Lock_），而不是只知道它可以用来对变量和方法进行加锁或同步。

锁是一种用来实现**线程安全类**的同步机制（_synchronization mechanism_）。一般我们很少
说一个程序是线程安全的，而是说某一个类是线程安全的，因此就有了类似`@ThreadSafe`这样的类注
解，所以我在这里强调了一下“类”，而不是泛泛地说线程安全。

那什么叫做“同步”呢？锁的作用具体体现是什么？下面举个简单的例子理解一下。

一般情况下Java对象是在JVM堆（_JVM heap_）上分配的，而堆是线程共享的内存区域。当某个堆变
量f在线程A和线程B间共享时，由于CPU缓存等原因，一个线程A对变量f的修改，另一个线程B可能无法
立刻看到，甚至于线程B永远都看不到线程A对变量f的最新修改。简单来讲，使用锁，就可以让线程B立
即看到变量f最新的值，这个机制就叫做同步，这里需要跨线程同步的就是变量f的最新的值。这有点类
似于在工作中，某个同事对你说：这个设计方案到时候也和测试和BI部门同步一下，保持相关同事对某
个信息都是知晓的。类似的，这种保持每个线程都能看到其它线程对某个共享变量的最新修改，就叫
做“可见性”。

当然，锁的作用不仅仅是保障变量的可见性，还有操作的原子性，顺序性等，这里就不详细展开了。

## 介绍显式锁

上面简单介绍了一下锁的作用，接下来的篇幅主要介绍显式锁（_explicit lock_）。`ReentrantLock`就
是jdk提供的显式锁实现之一。

与显式锁相对的是隐式锁（_implicit lock_），如果说`ReentrantLock`是显式锁，那么`synchronized`就
是隐式锁。实际上Java中所说的隐式锁就是指`synchronized`关键字实现的锁，而显式锁就是
指`Lock`和`ReadWriteLock`两个接口的实现。
